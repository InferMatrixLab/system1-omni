# pplx-decider-v1.1-27b

First step toward serving [perplexity-ai/pplx-decider-v1.1-27b](https://huggingface.co/perplexity-ai/pplx-decider-v1.1-27b/tree/14c9d90137962d300f3de95633f7b6535e80c5ce)
(Apache 2.0): a Qwen3.8-27B decision model that answers `choice`, `score` and `noul` from a 255-row readout at the
last position, with noncausal full attention and a fitted temperature. Its own server already speaks
`/v1/systemone`, so System1-Agents reaches it with no client change.

This crate holds the CPU half: the processor. There is no executor, worker binary or recipe yet.

- [`native/src/contract.rs`](native/src/contract.rs): request validation as the checkpoint's `server.EvaluationRequest`
  does it (unknown fields, 1 to 255 choice options, 2 to 10 score levels, `noul` criteria keyed `true`/`false`
  only, a string, object or array state); one prompt per question (`State:`, `Question:`, `Options:` with
  `A: key: description` lines and the 255 one-token answer codes `A`..`Z`, `AA`..`JT`); and the typed answers from
  the readout probabilities: the temperature and float32 softmax, then `answer` in float64 with Python 3.12's
  Neumaier `sum`, nothing rounded.
- [`native/src/processing.rs`](native/src/processing.rs): the system and user messages in the checkpoint's chat
  template with thinking off, the prompt token ids, the 8,192-token limit per question (rejected, never truncated),
  and the readout rows with their vocabulary ids for an `lm_head` export. Loading checks `decision_config.json`
  against the contract: format 1, codes, single-token ids, temperature, noncausal attention, last-token pooling.

## Reference

Everything follows `source/src/autojev` at 14c9d901 (`model.py` sha256 `02940963...`), the code the checkpoint
ships as its evaluated implementation.

## Limits (rejected with an error, not approximated)

- `images`: the vision lane is a later step.
- A prompt over 8,192 tokens.
- The executor must apply noncausal attention in the full-attention layers (the linear-attention layers keep their
  recurrence) and read the last position; the shared Qwen3.5/3.8 prefill is causal today.

## Tests

`tests/pplx_decider/data/contract.json` is generated by
[`tests/pplx_decider/make_fixtures.py`](../../../tests/pplx_decider/make_fixtures.py), which runs the checkpoint's code
unmodified without the weights: the server's request model, the prompt, the processor and chat template, and
`answer` on fixed readout logits. It records 15 questions in 9 requests (one is a recorded System1-Agents Google
Flights step) and 11 requests the server model rejects.

`tests/pplx_decider/data/hosted.json` is what the hosted model (OpenRouter, `perplexity/pplx-decider-v1.1-27b`,
build 20261006) answered to the same requests, recorded by
[`tests/pplx_decider/record_hosted.py`](../../../tests/pplx_decider/record_hosted.py), for the executor's parity
check later. Its `input_tokens` equal this processor's on every accepted request once questions with a single
option are left out: the hosted service answers those without the model (probability 1, 0 tokens), which the
checkpoint's server does not do. OpenRouter rejected three of the requests (a `noul` without criteria, object score
levels), which the checkpoint's server accepts.

```sh
cargo test --locked -p omni-pplx-decider-native
# with the pinned tokenizer.json and decision_config.json in a folder (no weights):
PPLX_DECIDER_MODEL=path/to/pplx-decider cargo test --locked -p omni-pplx-decider-native --test tokenization -- --ignored
```
