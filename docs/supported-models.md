# Supported models and hardware

This page distinguishes validated serving paths from experimental integrations.
Start with the
[CPU decision walkthrough](getting-started.md). The
[rolling model tracker (#83)](https://github.com/ThinkFlowLab/system1-omni/issues/83)
records available paths separately from proposed integrations and hardware evidence.
Models that are being added are also tracked in issues labeled [new model](https://github.com/ThinkFlowLab/system1-omni/issues?q=is%3Aissue%20state%3Aopen%20label%3A%22new%20model%22).

- **Validated:** covered by the recipe on `main` or by the checks in the linked merged pull request.
- **Author-run:** recorded by the recipe author on the stated hardware and not independently reproduced; the row names its owner.
- **Unverified:** the worker accepts this device, but no recipe or merged pull request covers it.
- **Planned:** not implemented yet; the linked issue tracks it.

The Cua-S1 workers answer `choice` questions only.
LAYA's English worker, Open-Jev and CLM support `choice`, `score`, and `noul` text questions.
D3's reference worker serves the same three kinds for text, image and video
state (inline base64 media under the pinned runtime's per-item budgets);
its media serving evidence is author-run on the A100 above.
pplx-decider's reference worker admits those three kinds for text and up to
four images. The checked path is the CPU contract. The kept Public231
primary is `4b99b73` in the table: p50 88.942 ms, p95 295.797 ms,
all-sequence FlashInfer with a 48-slot `cu_seqlens` ring. The prior
primary `ffae182` is p50 92.844 ms, p95 296.458 ms. `f968e576` is p50
94.077 ms, p95 300.200 ms, `fla-chunk` at compute capability 9.0.
Uncached all-sequence FlashInfer, the ≤256 FlashInfer
dispatch, cuDNN-first SDPA, the fused gate-up GEMM, and the three
compile tips missed the gate and are not the primary. Compile improved
p95 and raised p50, including after the median route proved eager. The
FlashInfer state-workspace ring `17a7b120` missed the gate (p50 89.165
ms, p95 295.723 ms) and is not the primary. Always-on FLA residual
RMSNorm `3afb472` missed the gate (p50 93.935 ms, p95 274.902 ms) and
is not the primary. Length-gated FLA residual RMSNorm `705ae089`
missed the gate (p50 94.604 ms, p95 274.835 ms) and is not the primary.
`use_cp=auto` `a6f4d9a` missed the gate (p50 112.294 ms, p95 299.419 ms) and is not the primary. Grouped-value `3ecdf5a` crashed in warmup (0/231) and is not a latency result. The packed-q/k candidate has no sample.
CLM has a row per path: the merged `clm-serve` recipe exercises those answer shapes with stub
embeddings and says nothing about decision quality, while the native engine's CUDA row is the
path through a real Qwen3-8B encoder. Its engine-only figure comes from the same comparison run
against the deterministic stub, where both sides get identical vectors; neither number validates
decision quality. MPS validation above is for a Python/PyTorch worker, not a native Metal backend.

The [architecture contracts](architecture.md) describe the native target.
Shared processing orchestration and dynamic batching remain planned. Native
workers reuse serial admission. Qwen workers run independent single-prompt
prefills with CPU heads; Laya packs questions within one request and runs its
scorer/action head on CUDA. These target layers do not expand
the validated model or hardware coverage above.
